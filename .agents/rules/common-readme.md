# Common README

Follow these conventions to keep the top-level `README.md` short and current. A
project rule can add to them.

1. **Keep only these sections:** what the project is, a table of contents, Updates,
   the sections that the project rule adds, Installation, Quick Start, and Citation.
   Keep the table of contents the same as the `##` sections, with the same emoji.
2. **Updates:** one dated line per user-facing milestone, newest first, such as a new
   feature. Write the date as `**[YYYY-MM-DD]**` in US Pacific time.
3. **Edit only when needed.** Update the README only when a user-facing change makes it
   wrong or incomplete, for example a new feature, dataset, model, or command. Never
   add implementation details, changelogs, or per-experiment notes.
4. **Edit an existing line if you can,** and do not add a new section.
